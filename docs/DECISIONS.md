# AI Lab — Decision Log

## How to use this document

Record only approved decisions. Do not rewrite previous decisions silently.

If a decision changes:

1. Keep the original entry.
2. Mark it as superseded.
3. Add a new decision explaining the change.

Decision statuses:

- `Accepted`
- `Proposed`
- `Superseded`
- `Rejected`

## Accepted decisions

### D001 — Preserve the original portfolio

- Status: Accepted.
- Decision: The current portfolio remains the default professional experience.
- Reason: It demonstrates Emad's manual development work and gives recruiters immediate access to essential information.

### D002 — Add a separate AI-assisted experience

- Status: Accepted.
- Decision: Add a second experience named AI Lab without replacing the original portfolio.
- Reason: The contrast between manual development and AI-assisted experimentation is central to the project.

### D003 — Voluntary activation

- Status: Accepted.
- Decision: AI Lab is activated through a visible user action.
- Current working label: `ACTIVATE AI LAB` / `ACTIVAR AI LAB`.
- Reason: The original portfolio must remain immediate and professional.

### D004 — Transformation narrative

- Status: Accepted.
- Decision: The original interface destabilizes, fragments, spirals into a singularity and reappears as a new universe after a cosmic explosion.
- Reason: The transition visually communicates the reinterpretation of handcrafted work through AI.

### D005 — Cosmic anomaly identity

- Status: Accepted.
- Decision: The central universe is based on black holes, gravity, spatial distortion and cosmic anomalies.
- Reason: This identity supports the transformation and allows different project worlds to coexist coherently.

### D006 — Preserve the Emad.dev visual lineage

- Status: Accepted.
- Decision: AI Lab retains dark foundations and electric blue accents from the current portfolio.
- Reason: The new universe must feel like an evolution of Emad.dev rather than an unrelated website.

### D007 — Real project worlds only

- Status: Accepted.
- Decision: Represent only projects that belong to Emad and have been verified.
- Current projects:
  - First Portfolio.
  - Temple of Fight.
  - Laboratorio GeoControl.
  - JS Quiz.
- Reason: The experience must remain professionally accurate.

### D008 — Transparent AI attribution

- Status: Accepted.
- Decision: Clearly distinguish the handcrafted original portfolio from the AI-assisted universe.
- Attribution principle:
  - Original portfolio: designed and developed manually by Emad.
  - AI Lab: concept and creative direction by Emad; development assisted by Claude; selected assets generated with tools such as Meshy.
- Reason: Transparency strengthens the project and prevents misleading authorship claims.

### D009 — Original experience must not pay the performance cost

- Status: Accepted.
- Decision: AI Lab and its heavy assets must be lazy-loaded.
- Reason: A visitor who only wants the professional portfolio should not download the complete 3D universe.

### D010 — Accessible parallel navigation

- Status: Accepted.
- Decision: 3D objects will have equivalent HTML navigation and controls.
- Reason: Essential content cannot depend only on WebGL, spatial understanding or pointer interaction.

### D011 — Sound is optional

- Status: Accepted.
- Decision: Sound is disabled by default and requires explicit activation.
- Reason: Avoid intrusive behavior and preserve accessibility.

### D012 — Reduced-motion and mobile alternatives

- Status: Accepted.
- Decision: Provide simplified transitions and visual profiles for reduced motion, mobile devices and weaker hardware.
- Reason: The creative concept must not exclude visitors or break devices.

### D013 — The project is not a videogame

- Status: Accepted.
- Decision: Use controlled camera journeys and direct navigation instead of mandatory free movement.
- Reason: The goal is a professional portfolio experience, not a game requiring learned controls.

### D014 — AI Lab button placement (resolves P004)

- Status: Accepted.
- Decision: Floating pill button anchored to the bottom-right corner, rendered once from `App.tsx` and visible across all sections.
- Reason: Stays accessible from Projects, Experience and Contact without modifying the header or hero layout, and keeps the original portfolio design untouched.
